## 二、难度与覆盖

所有题目的**主观估计难度**限制在 CF 1700～2400（不是虚构的官方 Rating），从易到难有梯度，建议 12 题目标难度为：

`1700, 1800, 1800, 1900, 1900, 2000, 2000, 2100, 2100, 2200, 2300, 2400`。

- 不能出现只需直接套 KMP、逐字符插入 Trie、基础回文判定等低于 CF 1700 水平的模板题。
- 不得为追求难度堆砌互不相关的算法；难度来自有价值的建模、性质发掘、关键转化、边界处理或数据结构结合。
- **任何一种具体的核心算法技巧、关键转化或解题模型，整套题中最多出现 2 次；优先每个独立核心思想只出现 1 次。**“换背景、换变量名、把计数改最值”不算新题。
- 六类算法各出现 2 次，但**同类的两题必须训练明显不同的关键思维**，不能只是同一个模板更换叙述。若出现跨算法结合，明确在内部指定唯一主要考点，并确保不使其他题的核心方法重复。
- KMP 与 Z 函数在前缀匹配、边界等方面容易互相替代；必须特别审查，避免它们的题目只是同一问题的两种写法。字符串哈希也不可沦为其他字符串算法题的通用替代实现。

可供选题参考的不同训练方向（仅用于内部设计，不要原样照搬或写进题面）：

| 算法 | 第一道的训练侧重点示例 | 第二道的训练侧重点示例 |
|---|---|---|
| KMP | 失配指针、border 链及其隐含结构 | 前缀自动机状态转移与计数/动态规划 |
| 字符串哈希 | 子串相等或 LCP 诱导的复杂查询 | 可修改字符串中的哈希维护与比较 |
| Trie | 前缀关系与集合计数的非平凡转化 | 字典树上的离线/持久化或结构性状态处理 |
| AC 自动机 | fail 树上出现次数或离线询问聚合 | 多模式状态约束结合动态规划/优化 |
| Manacher | 回文半径与区间统计的转换 | 回文结构与跨区间组合的最优化 |
| Z 函数 | 前缀匹配长度导出的覆盖/约束关系 | Z 数组性质与构造、分段或可行性判定 |

这些是**候选方向，不是指定题型**。如果发现两题机制重合，请更换核心构思，而非仅增加题面限制。

## 四、每道 Markdown 题面格式

严格参考区域赛题目，统一使用如下章节：

```markdown
# 题目 X：题目名称

## 题目描述

（给出独立、完整、无歧义的故事/数学定义与求解目标）

## 输入格式

（逐行解释输入）

## 输出格式

（输出内容、精度或取模要求）

## 数据范围与约定

（完整约束、字符集、总长度/总询问量、合法性与边界条件）

## 样例 1

**输入：**

```text
...
```

**输出：**

```text
...
```

## 样例 1 解释

（仅解释答案如何按题意得出，不提示解法）

## 样例 2

（同样给出输入、输出及必要解释）
```

要求：
- 使用简体中文、标准 Markdown 与正确的 LaTeX 数学格式；语句精确，尤其明确子串是否为空、下标从 0/1 开始、是否允许重叠、字典序定义、字符集、修改与查询是否影响后续状态。
- 一般至少 2 组经过人工推演或程序自检的有效样例，覆盖基础情况与易误解的边界。
- 保证约束与期望做法匹配：可在竞赛中合理时限通过，不要求依赖随机哈希无误判的“数学保证”；如确有概率正确性须说清楚，避免让题面暗示不成立的绝对保证。
- 如果题目存在多组测试，必须写清总规模限制。
- 禁止出现“本题考查 KMP/哈希/Trie/AC 自动机/Manacher/Z 函数”等暴露算法的内容；也不展示 CF 估计难度。

## 五、命题与自检流程（仅在内部完成）

1. 先拟定 12 题的内部规划表：题号、唯一主要算法、预计难度、关键思维、与其他题的区别。**仅供内部核验，不保存到仓库。**
2. 对每题先确定一个确切可行且复杂度适配数据范围的预期算法，再反推题面限制；确认解法不依赖未声明的条件。
3. 检查特例：空串/长度 1（若允许）、所有字符相同、全不同、大量重复模式、重复询问、查询边界、模数、动态更新顺序、总输入规模等。
4. 独立核对每个样例的输入合法性与输出正确性。发现无法验证或解法不成立时，**先修改题目，再交付**。
5. 统一检查题面格式与难度梯度，确保六类算法各恰好 2 题、全套核心思想不雷同且每题有独立教育价值。
